# Changelog

- **1.10.5** (2026-11-24): The capture scrolls each page to the bottom and back before the shots, so sections that fade in on scroll are reviewed (Astro run 1: every shot was blank below the hero); a `blank or hidden content` row means the page is not clean, and the review says what was not seen. Names Astro 7's `--ignore-lock` (and `npx astro dev stop`) beside the start command. `off-center columns` and `blank or hidden content` rows fail the applied change's check, like `mid-word breaks`, and the mid-word check now covers code set to break anywhere.
- **1.10.4** (2026-11-24): Before saying the picks are built, build or type-check the change when the project has a command for it, and say so if it fails or there is none (Angular run 1 never built). Commit only what you meant to change: a lockfile an install rewrote stays out of the commit, or is named in the message or PR. `off-center rows` in the capture table is a failure.
- **1.10.3** (2026-11-24): One build, then at most one correction pass: look at the review page once at 1280 after `--smoke` passes, fix what it shows in one pass, and stop. `--smoke` now prints each mockup box's width (`mockup_widths`), and a new item field, `stack_variants`, gives a desktop mockup a full row (SvelteKit run 1 spent five rebuild-and-capture rounds fighting a 500 px variant box). The start line uses `--port`, and exit 6 (an error page) is named.
- **1.10.2** (2026-11-23): `--smoke` flags any word a mockup breaks mid-word ("authenticat|ion"), naming the item and variant, with the same measure pr-qa's capture uses; fix the mockup or name it in the variant's note and do not recommend it. After applying picks, capture at 390, 1280 and 1440 plus a width just above each breakpoint the markup uses, and treat a mid-word break as a failure before saying the picks are built. A page wider than the phone is captured as a `zoomed` overflow instead of stopping the 390 run. On a phone the brand line's " · " separators hide, so none ends a wrapped line.
- **1.10.1** (2026-11-23): The review page's variant picker starts on the recommended variant (or the spec's `selected`), never blindly the first, so "Use Selected" untouched exports the recommended one; a `selected` that names no variant is a spec error. `@file:` paths in a spec fall back to the working directory, as asset paths do, and the error names both paths tried. At phone width the page's brand line wraps instead of cutting the session name, and the sticky bar keeps "X of N reviewed" and Copy on one row. Names `npx vue-tsc --noEmit` (or the project's own `npm run type-check` or `npm run build`) as the type check for a Vue app; the opt-in `--project` block now covers it and the Svelte, Astro and Angular checks.

- **1.10.0** (2026-11-23): When the app cannot start (a refused setup command, missing dependencies, a helper exit 3 or 4), the session stops before building anything and asks: (a) approve the exact setup commands, or (b) go ahead from committed screenshots labeled as not live. It never builds a review on committed screenshots unasked. Setup uses the forms the `--project` block now covers on non-Node stacks (for Django, `python3 -m venv .venv` and `.venv/bin/pip install -r requirements.txt`). Mockup fonts never depend on a download: copy the target page's own font `<link>` into `head_html`, or use the project's font files as assets, and end every `font-family` with a fallback stack that resembles it; the builder warns about a stack with no generic family. House rule 2: never `ls` or Read `~/.cache/proofs-playwright` to see whether Playwright is installed (outside the project, so the call is refused); the capture and `--smoke` report a missing install themselves.

- **1.9.0** (2026-11-22): Opens its saved page with exactly `open .proofs/pages/<name>.html`, which the opt-in `--project` allow block pre-approves; if `open` is refused it prints the path instead of retrying. Adds house rule 4: use the capture helper's own size and overflow checks, never `file`, `magick`, `identify` or `sips`, and change mockups with Edit or Write, never `sed -i`.

- **1.8.3** (2026-11-22): Says to run `--smoke` every time: if it reports Playwright missing, run the one-line install it prints (no browser download) and run it again; if it still cannot run, say on the page and in chat that the self-check did not run. It no longer reads as optional when Playwright is absent.
- **1.8.2** (2026-11-22): The capture example sets `CHROME` inside the `sh -c` capture command instead of in front of `python3`. Claude Code does not strip a `CHROME=` prefix before matching a Bash rule, so the old example never matched the unattended allow rule for the helper.
- **1.8.1** (2026-11-22): The capture example sets `CHROME` in the same command (a variable from an earlier Bash call is gone) and lists the usual Chrome paths. Says how to find the start command, to ask the user when there is none, and to pick an unused port so a stale app is not captured. Also: read the PNG to confirm the route, chain widths in one call, leave `.proofs/` untracked.
- **1.8.0** (2026-11-22): The "before" is always captured from the running app, through the new start-capture-stop helper, which works in `claude -p` and leaves no server running. A committed screenshot is used only when the app cannot run, labeled with its date and flagged to the user.
- **1.7.0** (2026-11-22): Runs its scripts (`review_page.py`) through `${CLAUDE_PLUGIN_ROOT}` and pre-approves them and reads of the plugin's own files, so a session no longer asks permission for each one.
- **1.6.2** (2026-11-21): The headless Chrome command adds `--disable-features=MacAppCodeSignClone`. On a Mac, Google Chrome copies its whole app (about 1.4 GB) into a temp folder on every launch and deletes it only on a normal quit, so screenshot runs left those copies behind.
- **1.6.1** (2026-11-19): Screenshots and photos show on older iPhones again (Safari before iOS 14 showed a broken "?"). Each WebP image now carries a PNG or JPEG fallback in a `<picture>`, and an image used more than once is filled in from a JSON map instead of a CSS variable older Safari could not read back. Pages are a little larger, by the size of the fallbacks.
- **1.6.0** (2026-11-19): The page's header now starts with the proofs mark and a `design-review` pill, then the project and the session (accented), on a slim line above the heading. Fill `project.session`; a page without it still builds, with a warning.
- **1.5.0** (2026-11-19): Fonts go in `assets` and are used from `css`, never pasted into the spec as base64 (one font was about 28,000 tokens). The builder embeds each asset once and converts screenshots to WebP: the smaller of lossy (quality 70) and lossless, shrunk to 1600 px wide only when that makes the file smaller. Delivers the page as "Where the page goes" says rather than always via artifacts. Says plainly that it needs the whole plugin.
- **1.4.1** (2026-11-18): Description trimmed to the trigger and how it differs from its nearest sibling; the detail it used to carry is in the body. No change in behavior.
- **1.4.0** (2026-11-18): The review page is now built by the shared, tested builder (`shared/review_page`): Claude writes the spec and the mockups, the builder supplies the buttons, variant gallery, read switch, sticky tally, export and clipboard fallback. Same page and export for the reviewer; a multi-variant Approve with Comment now names the selected variant.
- **1.3.3** (2026-11-18): Moved 'Where the page goes' to a shared reference file and the changelog to CHANGELOG.md; no change in behavior.
- **1.3.2** (2026-11-17): Copy buttons now fall back to a selectable text box when the clipboard is unavailable (as on a Wi-Fi-served page), and `wifi` mode is limited to a private network you trust.
- **1.3.1** (2026-11-16): New section "Where the page goes": a project can choose an artifact, a local file, or a file served on its own Wi-Fi.
- **1.3.0** (2026-11-16): Merged into proofs: generic, no project-specific steps. Includes: open decisions at the top, a "Mark as read" switch per item (read items leave the next round), selection marked with a border rather than a fill, and "Use Proposed" for single-option items.
