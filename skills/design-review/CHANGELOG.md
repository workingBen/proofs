# Changelog

- **1.13.0** (2026-11-27): Follow-up rounds start clean. Round 2 republished to the same URL used to pre-fill a changed item with round 1's decision and comment (an item id reused, so the saved answer came back). Every review item now carries a fingerprint of its proposal and round, saved with each answer, and an answer given on another version shows on the card read-only ("Round 1: Approve with Comment: …") with the buttons on Pending and the comment box empty; `--answers` and Copy leave it out. The same round reloaded or republished keeps every answer. Between rounds, §6 now puts the open items on top and every settled item in the spec's new `decided` list, folded at the bottom, and sets `project.round`; a read item gets a line there instead of being dropped.
- **1.12.0** (2026-11-26): The spend cap, port, option count (2 or 3), critic (helper or self) and correction passes (0 to 2) and the design profile path are read from the Proofs settings (`settings.py --print`) instead of fixed numbers; the defaults are unchanged (3311, $5, 3, helper, 1).
- **1.11.1** (2026-11-25): A menu row cut off at phone width is now reported. In a blind test, two options' top nav ran past the right edge of a 390px phone, cutting the last link mid-word ("Works with AI"), and `--smoke` said nothing: the row scrolls sideways inside itself, so the page never does, and nothing measured what a scroller hides. At 390, `--smoke` now finds any sideways-scrolling or clipped row whose item is only partly visible at its right edge and makes it a problem line (`1 row cut at the right edge at 390px ("Works with AI" cut)`). A row whose links sit wholly past the edge is the same bug, since a phone shows no scrollbar and the reader never knows they are there: `1 row hides 2 items past the right edge at 390px ("Works with AI helpers", "Dependable uptime")`. The design checks list both as `clippedRows`, with the hidden labels in `hidden`. A carousel whose next card peeks in (a card wider than half the row, with more than one line of text or a picture) is a deliberate swipe hint, so it is a note (`peekRows`), never a problem. A one-line link, tab, button or chip of any width is cut, not a card.
- **1.11.0** (2026-11-24): A better designer. An optional design profile (`docs/design-profile.md`, or `PROOFS_DESIGN_PROFILE`) is read when present; when missing, the skill says so in one line, offers to create one on two questions pages, and goes on without it: never required. A redesign gets three options with roles (Careful, Step up, Bold) that must differ in layout or hierarchy, and `--smoke`'s near-copy line is a problem to fix; a bug-sized fix or a "Found by the capture" item gets one option, its mockup wrapped in `<div class="rp-mockup">` so `--smoke` checks it. Each item names its section in the capture's `measures.json` and the builder reads it (`"before_sections": {"from": …, "page": …, "width": 1280, "label": …}`, and `before_font_sizes` the same way; a wrong label lists the labels the file has, and a malformed `before_sections`, `before_font_sizes`, `role` or `judged_by` is a one-line spec error), and every option carries an `inventory` of what it kept, moved or removed and why. `--smoke`'s `notes` (contrast not measured over images, off-scale type) go in the item's Reason and in chat, and "not measured" text is checked by eye. A critic scores the current page and every option against the new `reference/design-rubric.md`: a separate helper with a fresh context when the session can start one, else the session itself (`claude -p`), recorded as `judged_by` on every item with a mockup. The first build is a critic build (every item stacked, with no notes, reasons, recommendation, scores or `judged_by`), so the look's shots at 390 and 1280 show the critic each option at full width with no reasoning on it; the correction pass's rebuild adds the critic's results, and options below the bar are revised once or dropped inside that one pass. A "Found by the capture" item without a mockup carries no `inventory` or `scores`, and the builder now shows a one-option item's score row only when it has `scores` or `judged_by`, so copy-edit and capture items no longer say "Not scored". An `ACCEPT WITH COMMENT` that says to keep an element puts it back while applying, or asks when it cannot fit. Every option keeps the brand exactly as it is (logo, wordmark, company and product names, brand colors, taglines): the site's own logo file, never redrawn or replaced by text; Bold may change everything around it, never the brand. Brand rows in the inventory carry `"brand": true` and show a "Brand" tag, and a brand element removed or changed scores `care` 1, which fails the option and is never a carve-out. When the logo file is not in the project, the session says so and uses the capture's own logo crop. Only a requested rebrand changes the brand. Bold's new colors come from the site's palette, its style guide or the profile's Love references, which `fit` accepts; `fit` drops only for colors that clash with the brand or the profile or recolor a brand color. A Step up may trade one point elsewhere for a 2-point gain on the requested criterion, and is dropped ("Careful already at 5") when Careful scores 5 everywhere. `--smoke`'s design checks (contrast, tap targets, line length, edges, near-copies between options) run on design-review pages only, so style-guide and photo-picker pages are unchanged; contrast reads any CSS color (oklch included) and composites faded text, and what it cannot measure is a note. A one-option fix that keeps the page's layout is a note, not a problem. Results first: quality wins within the $5 est. per-run cap.
- **1.10.7** (2026-11-24): Applying picks changes only what was picked; anything else (shorter copy so a layout fits, a nearby section) is proposed, not applied, and mockups keep the page's copy (Astro run 3: a headline lost three words nobody picked). The after capture runs with `--compare .proofs/capture/before/measures.json`, and an entry new since the before in the changed area is a failure to fix before saying the picks are built, even when the total fell (3 of 9 small tap targets were new). Crops come from the capture's new `-part-NN.png` shots and the y in `measures.json`, never from a measuring page or CSS offsets, and "Found by the capture" items need no mockup. Commit, push and PR steps follow the new `reference/commit-and-pr.md`. **Results first** (the maintainer's principle): nothing matters more than a result the user wants; save tokens by cutting waste, never by cutting a check, an option or a revise pass the result needs. Full text is rule 0 in `reference/house-rules.md`.
- **1.10.6** (2026-11-24): Before saying the picks are built, run the project's type check as well as its build when it has a `tsconfig.json` and the change touches typed files (`npx tsc --noEmit`, `npx astro check` when `@astrojs/check` is installed, `npx vue-tsc --noEmit`, `npx svelte-check`, or its own script), and say that a Vite or Astro build alone does not check types (Astro run 2: a broken `.d.ts` passed `npm run build`). Applied picks are not committed unless the user asked; the change stays in the working tree and chat says so. Flaws the before capture finds outside the request go on the review page in a "Found by the capture" section, one accept-or-deny item each, not only in chat; a capture row is a failure only if this change caused it.
- **1.10.5** (2026-11-24): The capture scrolls each page to the bottom and back before the shots, so sections that fade in on scroll are reviewed (Astro run 1: every shot was blank below the hero); a `blank or hidden content` row means the page is not clean, and the review says what was not seen. Names Astro 7's `--ignore-lock` (and `npx astro dev stop`) beside the start command. `off-center columns` and `blank or hidden content` rows fail the applied change's check, like `mid-word breaks`, and the mid-word check now covers code set to break anywhere.
- **1.10.4** (2026-11-24): Before saying the picks are built, build or type-check the change when the project has a command for it, and say so if it fails or there is none (Angular run 1 never built). Commit only what you meant to change: a lockfile an install rewrote stays out of the commit, or is named in the message or PR. `off-center rows` in the capture table is a failure.
- **1.10.3** (2026-11-24): One build, then at most one correction pass: look at the review page once at 1280 after `--smoke` passes, fix what it shows in one pass, and stop. `--smoke` now prints each mockup box's width (`mockup_widths`), and a new item field, `stack_variants`, gives a desktop mockup a full row (SvelteKit run 1 spent five rebuild-and-capture rounds fighting a 500 px variant box). The start line uses `--port`, and exit 6 (an error page) is named.
- **1.10.2** (2026-11-23): `--smoke` flags any word a mockup breaks mid-word ("authenticat|ion"), naming the item and variant, with the same measure pr-qa's capture uses; fix the mockup or name it in the variant's note and do not recommend it. After applying picks, capture at 390, 1280 and 1440 plus a width just above each breakpoint the markup uses, and treat a mid-word break as a failure before saying the picks are built. A page wider than the phone is captured as a `zoomed` overflow instead of stopping the 390 run. On a phone the brand line's " · " separators hide, so none ends a wrapped line.
- **1.10.1** (2026-11-23): The review page's variant picker starts on the recommended variant (or the spec's `selected`), never blindly the first, so "Use Selected" untouched exports the recommended one; a `selected` that names no variant is a spec error. `@file:` paths in a spec fall back to the working directory, as asset paths do, and the error names both paths tried. At phone width the page's brand line wraps instead of cutting the session name, and the sticky bar keeps "X of N reviewed" and Copy on one row. Names `npx vue-tsc --noEmit` (or the project's own `npm run type-check` or `npm run build`) as the type check for a Vue app; the opt-in `--project` block now covers it and the Svelte, Astro and Angular checks.

- **1.10.0** (2026-11-23): When the app cannot start (a refused setup command, missing dependencies, a helper exit 3 or 4), the session stops before building anything and asks: (a) approve the exact setup commands, or (b) go ahead from committed screenshots labeled as not live. It never builds a review on committed screenshots unasked. Setup uses the forms the `--project` block now covers on non-Node stacks (for Django, `python3 -m venv .venv` and `.venv/bin/pip install -r requirements.txt`). Mockup fonts never depend on a download: copy the target page's own font `<link>` into `head_html`, or use the project's font files as assets, and end every `font-family` with a fallback stack that resembles it; the builder warns about a stack with no generic family. House rule 2: never `ls` or Read `~/.cache/proofs-playwright` to see whether Playwright is installed (outside the project, so the call is refused); the capture and `--smoke` report a missing install themselves.

- **1.9.0** (2026-11-22): Opens its saved page with exactly `open .proofs/pages/<name>.html`, which the opt-in `--project` allow block pre-approves; if `open` is refused it prints the path instead of retrying. Adds house rule 4: use the capture helper's own size and overflow checks, never `file`, `magick`, `identify` or `sips`, and change mockups with Edit or Write, never `sed -i`.
