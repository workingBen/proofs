1What you see

01

Your List, Tickable

Open items from TODO.md become a page you tick off

Your to-do file's open items are turned into a published page with a tick box and a note field for each. You work the list by clicking, not by editing a file.

1. Renew the payment key   
2. Choose a tax setting
3. Add search to the blog   
02

Five Clear Groups

Items sit under Yours, Decide, Build, Backlog and Ongoing

Every item belongs to one of five groups: things only you can do, decisions you owe, work Claude can build, later work, and long-running items. The group decides how a tick is handled afterward.

Decide1

Backlog6

03

A Count You Can Trust

Lines the page couldn't read are counted, not hidden

The status bar reads like "18 open · 3 unparsed" when some lines in the file couldn't be read, and each one is named with its line number and the reason. A confident number never quietly drops real work.

18 open · 3 unparsed
Line 42: finished item still in the list
Line 57: item outside any group
04

Copy From Anywhere

The copy button stays on screen as you scroll

Copy my replies sits in the pinned status bar as well as at the bottom, so on a phone you never scroll the whole list to find it.

3 of 14 tickedCopy my replies

2How you mark it

05

Done, But…

Add a note to any item as you tick it

Each item has an optional note, so an item can come back as "done, but the old key still works until Friday" rather than just a tick.

1. Renew the payment key
done, old key works until Friday
06

Ticks Stay With Their Item

Ticks and notes follow the item, not its position

Ticks and notes are saved against each item's title, not its number. When the list is renumbered, nothing slides onto the wrong item. Rewording an item clears its tick, since it is usually a new item.

Renew the payment keywas #3, now #1
note keptsame item
07

Same Link, Ticks Kept

The page updates at the link you already have

The page is always republished to the same link, so your saved ticks and notes and your open tab stay put.

Monday→Fridaysame link

3After you paste back

08

Your Word Is Final on Your Items

Ticks on things only you can do are archived as-is

A tick on a Yours or Decide item, like revoking a key or answering a question, can't be checked from the code, so it goes straight to the archive with your note.

Yours · Renew key→ archived
Decide · Tax setting→ archived
09

Code Claims Get Checked

Ticked build work is verified before it's archived

A tick on Build, Backlog or Ongoing work starts a check against the actual code and history, like a matching commit, a file, a passing test or a merged change. Only what holds up gets archived, with the evidence.

Build
Add search to the blog
commit found test passes change merged
10

Unproven Stays Open

If the work isn't there, the item stays open with a note

If the work isn't really there, the item stays on the list exactly where it was, with a dated note saying what was found. Nothing is archived on a tick alone.

3. Add search to the blogStill open
Checked Nov 2: not on main, branch still open.
11

No Guessing on Matches

If a reply could mean two items, you're asked which

Ticks are matched back to items by title. When a title could match more than one item, both are named and you choose, because archiving the wrong item can't be undone.

"Update the key" matches two items:
1. Payment key5. Map key
12

Archived, Not Deleted

Finished items move to a monthly archive with the evidence

Done items leave the live list for a monthly archive file, word for word, with the date, your note and what proved them done. The reasoning behind past work stays searchable.

archive · this month
Renew the payment key
  archived: Nov 2
  note: old key works until Friday
  evidence: ticked by you
13

Findings Aren't Tasks

Notes and rules go to the docs, not the to-do list

A root cause, a workaround or a standing rule is moved to the document that owns it instead of sitting in the list as fake work. What stays is real, open work.

Workaround for slow builds→ project notes
Add search to the blogstays a task
14

Safe to Paste Twice

Pasting the same reply again changes nothing

Anything a reply names is already gone from the list after the first paste, so pasting it a second time is harmless.

1st paste3 archived
2nd pastenothing to do

Tame an Overgrown List

Turns a to-do file full of old history into a clean list

For a to-do file that has grown into a log of finished work, a one-time adopt step first reports how many items are done versus open before anything changes.

Done214
Open19
Reported before anything moves
16

Open Items Checked First

Every supposedly open item is checked against the code

Before the list is rebuilt, each open item is checked to see whether it was quietly finished already. Items that turn out to be done go to the archive instead of staying on the list.

19 open on paper
7 already built→ archive
12 really open→ list
17

History Moved Exactly

Old entries move to monthly files, proven identical

Past entries are split into monthly archive files by their own dates, and every section is compared byte for byte before anything is written. If one doesn't match, nothing is written at all.

Oct matches Sep matches Aug matches
18

Every Move Explained

You get a report of where each item went and why

The adopt step ends with a report of what was already built, what was really a note and moved to the docs, and which group each remaining item landed in.

7 itemsalready built
3 itemsmoved to docs
12 itemssorted into groups

Where the Page Goes

A private link, a local file, or your Wi-Fi

Your project picks where review pages go: a private claude.ai link, an HTML file that opens in your browser, or that file served on your home Wi-Fi so a phone can open it. Nothing is ever uploaded or tunneled in the Wi-Fi mode, and the server stops when the review ends.
