1Starting a session

01

Hand It Over, Walk Away

Send reports one at a time or in a batch

Every message after you open the session is treated as a new item in the queue. Anything you send while an item is in progress waits its turn, so new reports never derail half-finished work.

header overlaps the logo on my phone
add a sort-by-date option
Queued: 2 · working on: 1
02

Screenshots On by Default

One line tells you screenshots are on; you can opt out

The session starts capturing screenshots of every visible fix without asking you a question first. A single line says so, and one reply turns them off for the rest of the session.

Screenshots ON. Tell me if you want them OFF.
Send first itemON
03

A Live Page From Item One

A tracking page goes up before the first fix ships

As soon as the first items arrive, a review page is published with one card per item. The same page is updated after every item, so you can follow along at one link instead of waiting for a summary at the end.

The Before, Caught in Time

Claude takes its own before shot when an item comes in

The before screenshot is captured the moment an item arrives, before any code changes, at both phone and desktop size. Once the fix is in, the old state is gone, so every item you review has something real to compare against.

2While it works

05

No “Go” Needed

Moves to the next item on its own, every time

When one item is done, the next one starts in the same turn. You never have to type continue, and a long turn is not treated as a reason to stop. It only pauses when the queue is empty, everything left is waiting on you, or something destructive needs your OK.

1 · shippednext →
2 · shippednext →
3 · buildingno pause
06

Test First, Every Fix

Each fix starts with a failing test

Every change is built test-first, the test suite is run until it is green, and the diff is reviewed before it is committed. A fast loop does not mean a sloppy one.

test: header fitsFAILfix → PASS
test written first suite green diff reviewed
07

One Fix, One Pull Request

Every item gets its own pull request, merged as it goes

Each fix lands on its own branch, cut fresh from the main branch, and its pull request is opened and merged in the same turn. Two items share a pull request only when they touch the same code, so any single fix can be found, reviewed or undone on its own. If your project requires a human review on every pull request, say so at the start and the fixes land as open pull requests instead.

Header overlapPR merged
Footer linkPR merged
Sort by dateBuilding
one branch each, fresh from main
08

Hard Calls Wait for You

Design choices and risky changes are flagged, not guessed

If an item is a matter of taste, could destroy data, is too big for a quick fix, or is unclear, it is logged for you instead of decided alone. Writing down the guess it would have made does not count as asking.

Redesign pricing tableFlagged
Reason: several good designs exist; this is your call.
09

Hard Bugs Still Get Fixed

A tricky bug is debugged, not handed back

Being hard to track down is not a reason to flag a bug. It gets investigated and fixed without you, and only a specific fact or decision that only you have is saved as a question.

save sometimes fails
reproduced root cause found fixed and tested
10

A Line Per Item

A short progress line after every item

After each item you get one line: what it was, whether it shipped or was flagged, and how many are left. It is there for you to glance at and needs no reply.

[3/7] Footer link: shipped.
      4 remaining.
[4/7] Pricing table: flagged.
      3 remaining.
11

Everything Written Down

Every item lands in your to-do file

Each item gets an entry in the project's to-do file with what was asked, why it happened, the approach and any assumption made in place of asking. Shipped items are checked off, so nothing ships silently.

- [x] Footer link (shipped)
- [ ] Sort by date
  Why: list is in insert order
  Assumed: newest first
- [NEEDS INPUT] Pricing table

Each card shows where it stands: Reported, In progress, Shipped or Flagged. A note box is there from the start, so you can add detail, change the request or drop it before any work begins.

4At the end

16

Questions Saved for the End

Solo work first, then your questions in one batch

Everything that can be finished without you is done first. Then all the questions are asked together, so you get one round of decisions instead of an interruption per item.

Items 1–6done solo
3 questions, asked together
17

Your Verdict on Each Fix

Four answers per shipped item, none pre-selected

Each shipped card offers Looks right, Comment, Request revision and Revert it. Nothing is picked for you, so a fix you never looked at reads as not yet reviewed rather than approved.

Looks rightCommentRequest revisionRevert it
nothing pre-selected
18

One Paste Back

Copy my decisions gathers every card's answer

One button copies every decision and note, from any card in any state, as plain text you paste into chat. A note on a reported item changes the request; a revision on a shipped one becomes a new item.

Copy my decisions

19

Every Flag Has a Next Step

Flagged items say where they go from here

Each flagged item lists why it was held back and the next step, such as a design review, a planning session or simply your decision. A chat recap lists what shipped, what was flagged and anything left half done.

Pricing table→ design review
New billing flow→ planning
Delete old accounts→ your call

5Long sessions

20

Save Points

Long sessions save their progress between items

A long session saves its progress at an item boundary when a big item finishes and the next is unrelated, after five shipped items, when its memory is half used, or before a clearly large item. Nothing is ever saved mid-item.

big item done, next unrelated 5 items shipped memory half used next item is large
Save point
21

Nothing Lost at a Save Point

Facts checked, everything filed, nothing left in chat

Before saving, it confirms every merge really landed and the tests pass. The handoff note lists the whole queue, what is merged, what is still open, decisions made, and anything you said that nobody has acted on yet.

Handoff
Queue: 8 items, each with its state
Merged (checked): 5
Open: 1 pull request, not yet verified
You said: keep the old icons
Pages: tracking page link
22

Keeps Going Afterward

One line, then straight on to the next item

A save point is announced in one line and the next item starts right away; you are never asked to restart the session. If you do clear it, the next session picks up from the handoff note without re-reading old work.

Save point→ item 6 starts
Session cleared→ resumes from note
23

Where the Page Goes

A private link, a local file, or your Wi-Fi

Your project picks where review pages go: a private claude.ai link, an HTML file that opens in your browser, or that file served on your home Wi-Fi so a phone can open it. Nothing is ever uploaded or tunneled in the Wi-Fi mode, and the server stops when the review ends.
