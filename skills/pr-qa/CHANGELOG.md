# Changelog

- **1.9.5** (2026-11-24): `pr_qa_page.py` takes a plain-string human finding as a `warning` with that text as its title (Angular run 1: strings crashed the build with `AttributeError`), and any other malformed meta (not JSON, an entry or finding of the wrong shape, a bad severity or recommendation) stops with one line naming the PR and the field, exit 1; the skill documents the finding shape. The default path builds or type-checks the PR's code when the project has a command for it and reports the result in `tests` (a failure is a blocker). A description that does not match the diff is a `warning` finding, with an example. `pr_qa_findings.py` warns when the PR adds an off-center row.
- **1.9.4** (2026-11-24): `pr_qa_findings.py` never calls a run clean when a capture failed (an error status or error page; SvelteKit run 1 scored two 404 pages "clean"). `pr_qa_page.py` resolves a relative `dir` from `meta.json`'s folder too, warns for every screenshot the page should carry and does not, and `--smoke` fails on each such gap unless the entry's `absent_reason` or new `missing_shots` gives a reason. The build prints one line per PR with the page's verdict and recommendation, which the chat reply quotes word for word. The start lines use `--port` (Vite rejects `-p`).
- **1.9.3** (2026-11-23): A page wider than the phone no longer stops the 390 capture as "not trustworthy": the capture records it as a failing `sideways scroll` (for example `17px, zoomed`, with the widest element) and keeps measuring, so a PR that fixes a phone overflow shows it before and after. The first line is now `printenv PROOFS_PAGES PROOFS_BASE_DIR`, the exact form the `--project` block allows. On a Rails app the base folder installs with `bundle install --gemfile .proofs/base/<app-dir>/Gemfile`, which the block now allows. The page header's " · " separators belong to the part after them, so none is left at the end of a wrapped line at 390.
- **1.9.2** (2026-11-23): The page embeds each screenshot as a WebP (or a JPEG when smaller), scaling a page taller than WebP's 16383 px limit down to fit: Vue run 1's six full-page shots go from a 14.1 MB page to 2.6 MB. With neither ImageMagick nor cwebp installed the PNGs go in as before.
- **1.9.1** (2026-11-23): When the PR's added lines use a responsive prefix (`sm:`, `md:`, `lg:`, `xl:`, `2xl:`), the capture adds one width just above that breakpoint (656, 784, 1040, 1280, 1552; at most two extra), labeled with its width on the page; an `lg:` two-column layout is no longer shot only at 390 and 1440. The opt-in `--project` allow block now covers the read-only `gh pr diff` and `gh pr view`, used to check another open PR for overlap.
- **1.9.0** (2026-11-23): Names the forms to use on a non-Node app, which the `--project` allow block now covers (for Django: `python3 -m venv .venv`, `.venv/bin/pip install -r requirements.txt`, `.venv/bin/python manage.py runserver` through the helper, `.venv/bin/python manage.py test`), and `--stack` for a project with no marker file. House rule 2: never `ls` or Read `~/.cache/proofs-playwright` to see whether Playwright is installed (outside the project, so the call is refused); the capture and `--smoke` report a missing install themselves.

- **1.8.0** (2026-11-22): The page lists the other open PRs it skipped, even when there are no PRs to cover, and entries without a number are left out. A rise in small text or tap targets, including repeated small labels, now holds back a merge recommendation until it is explained. A rise means more items than before; a relabel with the same count is a plain warning. `meta.json` as an object must have a `prs` list and only the keys `prs` and `skipped`. The `--smoke` self-check has a timeout and does not open the page. A browser that will not start makes it exit 2 with an install hint, not 1. The skill opens its saved page with exactly `open .proofs/pages/<name>.html`, which the opt-in `--project` allow block pre-approves. If `open` is refused it prints the path instead of retrying. The up-front list names that `open` and the `--smoke` call as extras. The call counts are true: the no-PR path counts two extra `cp .env` calls. House rule 4: use the helpers' own checks, not `file`, `magick` or `sed -i`. The page builder creates `.proofs/pages` on a first run instead of crashing.

- **1.7.5** (2026-11-22): Removes the `.proofs/base` worktree right after the before shots are taken and read, before checking out the branch or running its tests, so test runners and linters that walk the tree cannot pick up the base copy. Common Mistakes keeps the cleanup as a backstop.
- **1.7.4** (2026-11-22): The capture example sets `CHROME` inside the `sh -c` capture command instead of in front of `python3`, so the command matches the unattended allow rule for the helper.
- **1.7.3** (2026-11-22): `pr_qa_findings.py` says "not measured" instead of "clean" when the evidence holds no measurements, decided per route so a partly measured run never reads clean.
- **1.7.2** (2026-11-22): New `PROOFS_BASE_DIR` setting moves the before-shot base worktree to `$PROOFS_BASE_DIR/<repo folder name>-pr-qa-base`, for setups that block `git worktree add` inside code folders. Unset, it stays `.proofs/base`.
- **1.7.1** (2026-11-22): Names the helper's log for each run (`.proofs/base/.proofs/server.log` for the before run, `.proofs/server.log` for the after run) and which `node_modules` the before capture resolves Playwright from.
- **1.7.0** (2026-11-22): Before shots come from a worktree at `.proofs/base`, with its own installed dependencies, and every capture runs through the start-capture-stop helper.
- **1.6.0** (2026-11-22): Runs its scripts (`pr_qa_page.py`, `pr_qa_findings.py` and `pr_qa_plan.py`) through `${CLAUDE_PLUGIN_ROOT}` and pre-approves them and reads of the plugin's own files, so a session no longer asks permission for each one.
- **1.5.1** (2026-11-21): The headless Chrome command adds `--disable-features=MacAppCodeSignClone`. On a Mac, Google Chrome copies its whole app (about 1.4 GB) into a temp folder on every launch and deletes it only on a normal quit, so screenshot runs left those copies behind.
- **1.5.0** (2026-11-19): The top bar starts with the proofs mark and a `pr-qa` pill, then project · session · repo; the "PR QA" label is gone. New `--session` flag on `pr_qa_page.py`; without it the page builds and says it has no session.
- **1.4.5** (2026-11-19): Says plainly that it needs the whole plugin, for anyone who copies one skill folder on its own.
- **1.4.4** (2026-11-18): Description trimmed to the trigger and how it differs from its nearest sibling; the detail it used to carry is in the body. No change in behavior.
- **1.4.3** (2026-11-18): Moved 'Where the page goes' to a shared reference file and the changelog to CHANGELOG.md; no change in behavior.
- **1.4.2** (2026-11-17): Copy buttons now fall back to a selectable text box when the clipboard is unavailable (as on a Wi-Fi-served page), and `wifi` mode is limited to a private network you trust. The session reminder now ships as a plugin hook that stays off until `PROOFS_PR_REMINDER=1` is set (the installer sets it); no path is written into project settings. Invocations use `/proofs:pr-qa`.
- **1.4.1** (2026-11-16): New section "Where the page goes": a project can choose an artifact, a local file, or a file served on its own Wi-Fi.
- **1.4.0** — Merged into proofs: generic, no project-specific steps.
