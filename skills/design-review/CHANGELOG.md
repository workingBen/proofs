# Changelog

- **1.8.2** (2026-11-22): The capture example sets `CHROME` inside the `sh -c` capture command instead of in front of `python3`. Claude Code does not strip a `CHROME=` prefix before matching a Bash rule, so the old example never matched the unattended allow rule for the helper.
- **1.8.1** (2026-11-22): The capture example sets `CHROME` in the same command (a variable from an earlier Bash call is gone) and lists the usual Chrome paths. Says how to find the start command, to ask the user when there is none, and to pick an unused port so a stale app is not captured. Also: read the PNG to confirm the route, chain widths in one call, leave `.proofs/` untracked.
- **1.8.0** (2026-11-22): The "before" is always captured from the running app, through the new start-capture-stop helper, which works in `claude -p` and leaves no server running. A committed screenshot is used only when the app cannot run, labeled with its date and flagged to the user.
- **1.7.0** (2026-11-22): Runs its scripts (`review_page.py`) through `${CLAUDE_PLUGIN_ROOT}` and pre-approves them and reads of the plugin's own files, so a session no longer asks permission for each one.
- **1.6.2** (2026-11-21): The headless Chrome command adds `--disable-features=MacAppCodeSignClone`. On a Mac, Google Chrome copies its whole app (about 1.4 GB) into a temp folder on every launch and deletes it only on a normal quit, so screenshot runs left those copies behind.
- **1.6.1** (2026-11-19): Screenshots and photos show on older iPhones again (Safari before iOS 14 showed a broken "?"). Each WebP image now carries a PNG or JPEG fallback in a `<picture>`, and an image used more than once is filled in from a JSON map instead of a CSS variable older Safari could not read back. Pages are a little larger, by the size of the fallbacks.
- **1.6.0** (2026-11-19): The page's header now starts with the proofs mark and a `design-review` pill, then the project and the session (accented), on a slim line above the heading. Fill `project.session`; a page without it still builds, with a warning.
- **1.5.0** (2026-11-19): Fonts go in `assets` and are used from `css`, never pasted into the spec as base64 (one font was about 28,000 tokens). The builder embeds each asset once and converts screenshots to WebP: the smaller of lossy (quality 70) and lossless, shrunk to 1600 px wide only when that makes the file smaller. Delivers the page as "Where the page goes" says rather than always via artifacts. Says plainly that it needs the whole plugin.
- **1.4.1** (2026-11-18): Description trimmed to the trigger and how it differs from its nearest sibling; the detail it used to carry is in the body. No change in behavior.
- **1.4.0** (2026-11-18): The review page is now built by the shared, tested builder (`shared/review_page`): Claude writes the spec and the mockups, the builder supplies the buttons, variant gallery, read switch, sticky tally, export and clipboard fallback. Same page and export for the reviewer; a multi-variant Approve with Comment now names the selected variant.
- **1.3.3** (2026-11-18): Moved 'Where the page goes' to a shared reference file and the changelog to CHANGELOG.md; no change in behavior.
- **1.3.2** (2026-11-17): Copy buttons now fall back to a selectable text box when the clipboard is unavailable (as on a Wi-Fi-served page), and `wifi` mode is limited to a private network you trust.
- **1.3.1** (2026-11-16): New section "Where the page goes": a project can choose an artifact, a local file, or a file served on its own Wi-Fi.
- **1.3.0** (2026-11-16): Merged into proofs: generic, no project-specific steps. Includes: open decisions at the top, a "Mark as read" switch per item (read items leave the next round), selection marked with a border rather than a fill, and "Use Proposed" for single-option items.
